# ══ 01. AI PROTOCOL — HOW EVERY PATCH SESSION RUNS ════════════════════════════
# the chunk section is the contract · these keys define the execution + bookkeeping rules
ai.unit-of-work = ONE chunk per patch session — open its §05-08 block, finish ALL of its open (status = todo) features in one pass, then stop
ai.order = chunks run in id order within a phase · a chunk whose chNN.deps are not ALL status = done is BLOCKED — never start it
ai.budget.k = 40
ai.budget.zone = green ≤ 40k · yellow ≤ 50k (1.25×) — split or trim first if open user features push it further · red > 50k — must split
ai.split.rule = over-budget chunk → duplicate it as chNNb (title "… (part 2)", deps = chNN, move half the open features in, est.out.k halved) and run as two sweeps · never renumber existing ids
ai.read.rule = grep chNN.files first, read only the relevant functions — read cost is est.read.k (formula in §03); do not whole-file dump 59k world.js into context when a section will do
ai.output.rule = unified diffs or changed functions only — never re-emit whole files · touch no files outside chNN.files unless unavoidable (say why)
ai.saves.rule = keep localStorage saves backwards compatible (ac-meta-v2 / ac-save-v1) · migrations idempotent, no lost power, no lost currency
ai.scope.rule = the chNN.fX.text lines are the contract — implement ALL of each one, no silent scope cuts · ASSUMPTION notes inside a text must be confirmed or replaced with a stated decision before coding
ai.stop.rule = running short on budget → stop at a clean boundary, log remaining work as new chNN.fX lines (status = todo) and say what is left
ai.markers.rule = leave a /* CH-NN.X */ comment at each implemented feature (existing pattern: see CH-01.x / CH-02.x markers in the patched zip) — the next session verifies from markers, not re-reads
ai.deliverable = every patch ships TWO artifacts — (1) the NEXT ITERATION of the full game zip: re-zip the whole folder (index.html + css/ + js/ + README.md) as frame-scape-v<current>-ch<NN>-patched.zip (version part bumps only when a phase version lands) · (2) THIS file updated per ai.finish.file + ai.finish.worklog — ship both, the bridge breaks otherwise
ai.interrupt.rule = requests the user types MID-RUN are registered immediately with a fresh permanent id (§09 inbox line or routed chNN.fX) — never dropped, never held in memory — but they do NOT widen the running sweep; they schedule through the normal plan rules once the current chunk closes
ai.projection.rule = follow-up work discovered while patching (placement passes, migrations, balance, fixes, polish) is REGISTERED, not remembered — new chNN.fX lines in the current chunk, or a projected new chunk per ai.new-chunk.rule · every §12 worklog follow-up must point at a line that exists in this file
ai.new-chunk.rule = a request or projection that matches no open chunk becomes a NEW chunk block: next free CH-NN id inside the matching phase section (new phase block if it starts one), carrying title · size · files · deps · keywords · est keys — then it competes for plan.next in id order
ai.finish.test = end the reply with a 5-line manual test checklist for the patch
ai.finish.line = then one line exactly like: done|CH-03.1,CH-03.2 (remove ids you did not finish)
ai.finish.file = then update THIS file — chNN.fX.status = done for finished ids · chNN.status = done when all its fX are done · plan.next recomputed · meta.last-patch + meta.game.version updated
ai.finish.worklog = then append a §12 worklog entry (next worklog.N): date · chunk · summary · files touched · code markers left · follow-ups
ai.routing.rule = a new request is keyword-matched against every open chunk chNN.keywords (case-insensitive substring, most hits wins, first in id order breaks ties) → routed there · no hit → stays in §09 inbox · done chunks and §10 parked are never routed to
ai.prompt.recipe.1 = PROJECT: Frame Scape (vanilla ES modules + three.js r152, no build step, i3/HD3000 perf budget; all tunables live in js/assets.js)
ai.prompt.recipe.2 = TASK chNN: chNN.title
ai.prompt.recipe.3 = RULES: ai.read.rule · ai.output.rule · ai.saves.rule · ai.scope.rule · ai.stop.rule (this section)
ai.prompt.recipe.4 = FILES: chNN.files
ai.prompt.recipe.5 = DEPENDS ON (already shipped): chNN.deps
ai.prompt.recipe.6 = FEATURES: the open chNN.fX lines as "N. [CH-NN.X] text"
ai.prompt.recipe.7 = FINISH BY: a 5-line manual test checklist, then one line exactly like done|CH-03.1,CH-03.2 (remove ids not finished)
ai.prompt.recipe.note = paste recipe + the chunk whole §05-08 block into a fresh AI session when running the patch — that keeps the session inside one sweep budget

# ══ 02. USER PROTOCOL — HOW TO DRIVE THE PLAN ═════════════════════════════════

user.sort = the AI routes new lines by ai.routing.rule · override it by moving a line into any chNN block yourself (keep the id, update the id prefix)

user.versions = a phase version (§04) lands when its last chunk is done · README.md "What's new" is updated at version bumps
